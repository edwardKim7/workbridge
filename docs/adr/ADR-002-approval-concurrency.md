# ADR-002: 결재 중복 처리를 조건부 UPDATE로 차단

- 상태: 승인

## 배경

모바일에서 승인 버튼을 연속으로 누르거나 같은 요청이 재전송되면 결재가 두 번 처리될 수 있습니다. 화면에서 버튼을 잠그는 것만으로는 다른 기기나 동시 요청을 막을 수 없습니다.

## 결정

1. Flutter는 요청 처리 중 버튼을 비활성화합니다.
2. Service는 승인자, 상태 `REQUESTED`, 요청 `version`을 확인합니다.
3. DB는 `approval_id + approver_id + status + version` 조건으로 UPDATE합니다.
4. UPDATE가 1건일 때만 성공으로 처리합니다.
5. 상태 변경과 `approval_history` 저장은 같은 트랜잭션에서 처리합니다.
6. UPDATE가 0건이면 재조회 후 403, 404, 409 중 하나로 반환합니다.

## 이유

최종 중복 방지는 DB가 맡습니다. 단일 DB 구성에서는 별도 분산 락 없이 상태와 버전 조건만으로 처리할 수 있습니다.

## 대안

- 모바일 버튼 비활성화만 사용: 다른 클라이언트와 재전송을 막지 못합니다.
- Java `synchronized`: 서버가 여러 대면 동작하지 않습니다.
- 비관적 락: 현재 처리 시간과 충돌 빈도에 비해 잠금 범위가 커집니다.

## 확인 항목

- 같은 ID와 버전의 승인 요청 두 건 중 한 건만 성공
- 나머지 요청은 `409 APPROVAL_ALREADY_PROCESSED`
- 승인 이력은 한 건만 저장
- Flutter에서 처리 중 두 번째 탭은 API를 호출하지 않음
